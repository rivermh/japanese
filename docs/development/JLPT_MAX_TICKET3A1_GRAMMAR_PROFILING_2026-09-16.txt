12. Kind DISTINCT VALUES ANALYSIS (actual, this run)
================================================================================

Kind distinct raw values -> count: {'⁣' -> 3,605}

**Every single one of the 3,605 grammar-model notes has the exact same Kind
raw value: U+2063 INVISIBLE SEPARATOR (rendered here as '⁣'), Anki's standard
placeholder for a visually-empty field.** This holds across every category,
every Level, and every Is*-flag combination (verified: Kind x category, Kind
x Level, Kind x flag-combo all show only this one value).

`AnkiFieldTextNormalizer.text()` (already used elsewhere in the codebase)
explicitly strips U+2063 before checking blankness
(`raw.replace("⁣", "")...isBlank()`), so `GrammarHtmlParser`'s existing
`connection = AnkiFieldTextNormalizer.text(kind)` call already normalizes
this to `null` for all 3,605 notes today — i.e. `Grammar.connection` is
currently always null/absent for every JLPT-MAX-Deck v2.1.1 note, and this
is correct behavior, not a bug.

**Kind carries zero grammatical-connection information in this dataset.**
"Kind" is a leftover/unused field name in this Anki note type - possibly used
by a different note-type or an earlier deck version - not a marker of
grammatical conjugation/connection form.

16. COMPREHENSIVE CONTENT CLASSIFICATION (actual, this run)
================================================================================

**COMPREHENSIVE Grammar (2,527 notes, minus the 371 SentenceArrangement
subset handled separately in section 17) is structurally a multiple-choice
fill-in-the-blank PRACTICE/QUESTION item, not a Grammar knowledge-content
entry.** Evidence, all from real DOM structure (not just category/field
names):
- Zero notes have the structured explanation div (`div._j4z`) or the
  structured example section (`section._j4a`) that normal GRAMMAR always has
  — this content was never authored in a "pattern + explanation + examples"
  shape.
- Every note has a Korean instruction prompt (`div._jbp`, "빈칸에 들어갈
  가장 알맞은 것을 고르세요" = "choose the most appropriate one to fill in
  the blank" pattern text observed), a stem with one highlighted blank
  (`mark._j4y` inside `div._jby`), a Korean translation (`div._jbz`), and a
  4-item ordered list of answer choices (`ol._jbx` > `li._jbr`) with exactly
  one `li.is-correct` per note (2,156/2,156 = 100% of the non-arrangement
  subset).
- This maps directly onto ticket category B ("Grammar Practice / Question":
  prompt, blank, choices, answer, explanation) from the ticket's own
  A-F classification list — not A (knowledge content: pattern/explanation/
  examples).

Recommendation: model this as a Practice/Question-domain entity (or a
dedicated GrammarComprehensionQuestion-style shape), not as an extension of
the existing Grammar entity's pattern/explanation/examples fields. Forcing it
through `GrammarHtmlParser`'s current selectors (as the extractor's
`normalized()` preview path already does, incidentally) produces the
misleading "explanation via fallback" and "0 examples" symptoms documented in
Ticket 1 and reproduced again in section 18 below - those are not parser bugs
to fix, they are a sign the wrong extraction shape is being applied to this
content.
